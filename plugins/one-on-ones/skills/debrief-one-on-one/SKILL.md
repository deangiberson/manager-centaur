# Debrief a one-on-one

Work only in the private workspace. Do not update the shared document.

## Verify the input

Confirm the report, meeting date, transcript, and private-memory target. Check
that transcript consent and retention requirements in settings.md are met.

If the transcript is missing, incomplete, or assigned to the wrong meeting,
stop or use manager-supplied notes while clearly recording the limitation.

## Write the private journal entry

Ground the meeting record in the transcript. Add:

1. Discussion summary
2. Explicit decisions
3. Action items
4. Open questions
5. Manager thoughts

Assign an action owner or due date only when explicitly stated. Mark unclear
language for review rather than resolving it by inference.

Add manager thoughts only from thoughts the manager supplies. Keep them
separate from the transcript-grounded record.

Create or replace one marked debrief block for the report and date so rerunning
does not duplicate content.

## Propose durable-memory changes

Copy private/people/<id>.md to
private/proposals/<date>-<id>-memory.md. Edit only the candidate and show the
manager its diff from the durable memory.

Propose only information useful beyond the current journal entry:

- Confirmed context, with date and source
- Explicit preferences or career goals
- Open or completed commitments
- Recurring topics
- Manager observations or hypotheses, clearly labelled
- Stale entries to remove

Do not invent traits, diagnoses, motives, performance conclusions, or company
policy.

Apply the candidate to private/people/<id>.md only after explicit manager
approval. Preserve the original when approval is absent.

## Hand off publication

When debrief and memory review are complete, identify the exact shared-document
and transcript files eligible for release. Do not prepare shared minutes in
this session.

Tell the manager to create an allowlisted release bundle and start a fresh,
isolated Claude Code session for publish-one-on-one-notes.
